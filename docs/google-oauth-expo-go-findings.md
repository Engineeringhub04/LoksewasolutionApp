## Code review conclusion

The app uses `expo-auth-session` browser OAuth and sends Google an Expo Go redirect URI. The error occurs before Firebase token exchange, so Firebase `signInWithGoogleIdToken()` is not the immediate failure point. The exact Expo Go redirect URI is not shown as registered/allowlisted in the provided screenshots. The mobile iOS/Android client IDs alone do not fix an Expo Go browser redirect; the Web OAuth client and exact redirect flow must be aligned.

## Official Expo documentation

Expo authentication guide: https://docs.expo.dev/guides/authentication/

Expo AuthSession reference: https://docs.expo.dev/versions/latest/sdk/auth-session/

Key points from the official docs: use `AuthSession.makeRedirectUri()` for platform-aware redirects; OAuth providers require the redirect URL to be allowlisted; Expo Go cannot be used for local development/testing of OAuth/OIDC apps when the app scheme must be customized, and a development build is recommended; standalone/development builds use a configured scheme such as `loksewasolutionapp://...`; AuthSession is a browser-based flow and uses WebBrowser.

## Current SDK 54 verification

The installed Expo SDK 54 `expo-auth-session` still contains the deprecated `getRedirectUrl()` proxy helper. Its `makeRedirectUri({ scheme })` implementation intentionally generates an `exp://...` URI in Expo Go and a custom scheme in standalone/development builds. The installed Google provider selects `androidClientId`/`iosClientId` on native platforms and falls back to `clientId`; it auto-exchanges native authorization codes and exposes the resulting `id_token`.

Expo's current official guidance says Expo Go cannot be used for local OAuth/OIDC testing when a custom app scheme is required, and recommends a Development Build. The legacy proxy service remains available but is deprecated and cookie-dependent. Sources: https://docs.expo.dev/guides/authentication/ ; https://docs.expo.dev/guides/google-authentication/ ; https://docs.expo.dev/versions/latest/sdk/auth-session/ ; https://auth.expo.io/

For this PR, the requested best-effort Expo Go fallback will use the legacy proxy only in Expo Go, while native Development/Production builds will use the `loksewasolutionapp://oauthredirect` scheme and platform client IDs. This fallback may still be affected by Expo proxy deprecation/cookie behavior; production will use the supported direct native redirect flow.
